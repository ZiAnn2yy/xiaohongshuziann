# 内容增长知识库（Content Growth Knowledge Base）

用于把新闻学、传播学、营销学、增长学与短视频实战方法整合成可执行框架，支持选题、脚本、拆解、增长实验与复盘。

## 使用边界

1. 若没有原书全文，只输出基于公开理论与书名方向的结构化知识框架，不伪造“逐章精读”细节。
2. 若用户提供电子书、笔记、摘录或课程资料，优先基于用户材料做二次抽象。
3. 结论必须落到可执行项：指标、动作、实验或模板，避免纯概念罗列。

## 触发场景

- 用户要搭建内容方法论、知识库、学习地图
- 用户要拆解爆款视频、优化脚本、提升留存/转化
- 用户要做定位、传播路径、用户需求分析
- 用户要把理论转成运营动作、SOP、实验方案

## 执行流程

按以下流程输出，不跳步：

1. **定义目标**
   - 明确业务目标：涨粉、完播、互动、转化、复购中的哪一项优先
   - 明确内容形态：口播、剧情、知识型、测评、直播切片等
2. **选择知识域**
   - 从“核心理论 / 传播机制 / 营销转化 / 增长运营 / 实战案例 / 工具方法”中选 2-4 个主域
3. **抽取关键变量**
   - 每个主域至少产出 3 个变量（如“新闻价值密度”“认知负荷”“承诺一致性触发点”）
4. **建立因果链**
   - 用 `输入 -> 机制 -> 行为 -> 指标` 形式串联变量
5. **产出执行件**
   - 至少输出一种：脚本模板、拆解表、实验计划、复盘卡
6. **定义验证方案**
   - 给出可观测指标、样本周期、对照组与停止条件

## 书目知识图谱（按领域）

### 1) 核心理论类（产品学术框架）

- `新闻采访与写作`：信息价值、叙事结构、导语与事实组织
- `新闻报道学教程`：新闻价值判断体系（时效性、重要性、接近性、冲突性等）
- `叙事学导论`：叙事时间、视角、话语层级，用于文本/视频结构建模

### 2) 传播学类（传播机制）

- `传播学概论`：传播链路（编码-媒介-解码-反馈）与受众效果
- `媒介生态`：媒介形态改变信息意义，平台机制会重塑表达策略
- `Uses and Gratifications Theory`：受众主动性与需求满足（信息、情感、社交、身份）

### 3) 广告学/营销类（召回与转化）

- `定位`：心智空位、差异化锚点、竞争参照系
- `影响力`：互惠、承诺一致、社会认同、权威、稀缺、喜好等说服线索
- `突破传播`：整合传播路径，从曝光到互动再到转化

### 4) 运营与增长类（实践模型）

- `增长黑客`：增长循环、实验驱动、AARRR 指标框架
- `用户故事地图`：用户任务流与场景分层，映射内容触点
- `Hooked`：触发-行动-可变奖励-投入，构建习惯与留存

### 5) 实战案例类（爆款拆解）

- `脚本思维`：内容模块化拆解（开场钩子、冲突、转折、兑现）
- `社交媒体内容策划与运营`：平台机制、内容节奏、账号协同
- `短视频营销与传播案例集`：行业案例模板与策略对照

### 6) 工具方法类（分析与表达）

- `系统思考`：把内容问题转成系统变量和反馈回路
- `认知负荷与信息设计`：减少理解阻力，优化信息分层与节奏
- `数据可视化实用指南`：把分析结果做成可传播图表与看板

## 输出模板

### 模板 A：单本知识卡

```markdown
# [书名] 知识卡
- 核心命题：
- 关键概念（3-5个）：
- 适用场景：
- 不适用场景：
- 可执行动作（3条）：
- 可监测指标（3个）：
```

### 模板 B：爆款内容拆解卡

```markdown
# 爆款拆解卡
- 内容类型：
- 目标人群与需求（U&G）：
- 叙事结构（开场-冲突-转折-兑现）：
- 传播机制（平台/社交扩散）：
- 说服策略（影响力原则）：
- 留存与互动触发点（Hooked）：
- 指标表现（完播/互动/转化）：
- 可复用策略（保留）：
- 风险点（避免）：
```

### 模板 C：增长实验卡

```markdown
# 增长实验卡
- 假设：
- 理论依据（对应书目）：
- 变更项（脚本/封面/标题/节奏/CTA）：
- 对照设计：
- 观察周期：
- 成功阈值：
- 失败止损条件：
```

## 响应风格要求

1. 先给结构，再给案例，再给行动建议。
2. 术语必须附一句“业务语言翻译”。
3. 每次输出都要包含“下一步可执行动作（不超过 5 条）”。
4. 用户未提供材料时，显式标注“基于公开理论框架推断”。

## 有新材料时的更新规则

当用户提供书摘、PDF、课程笔记或案例数据时：

1. 先抽取新概念并归入六大领域。
2. 再更新变量字典与模板字段。
3. 若出现冲突观点，保留“观点 A / 观点 B / 适用边界”。
4. 最后输出“知识库增量更新记录”。
